# ЛР4. Сегментация полутоновых изображений методом Оцу

Готовый отчёт: [output/pdf/report.pdf](output/pdf/report.pdf). Исходник: `report.tex`, текстовые части — `docs/*.tex`. Оформление по указанному скиллу `aa-report-gost-skill`, преамбула v2 без изменений.

Реализация — **C11** и POSIX Threads. Один диспетчер и ровно q рабочих потоков одного вида. У каждого рабочего две фазы: локальная гистограмма → ожидание общего порога → маска своего диапазона. Между фазами выполняется объединение гистограмм и поиск порога диспетчером. При q=1 всё равно создаётся рабочий поток. При q>N создаются q потоков, пустые диапазоны допустимы.

## Сборка и проверки (Windows)

Нужны GCC MSYS2 UCRT64 с winpthreads (каталог `C:\msys64\ucrt64\bin` в PATH) и Python 3. Для отчёта — XeLaTeX/MiKTeX, Times New Roman, Arial; для графиков — matplotlib и Pillow.

```powershell
./build.ps1
./segment.exe generate 512 512 20261112 input.pgm
./segment.exe segment seq input.pgm seq.pgm
./segment.exe segment par 4 input.pgm par.pgm
./segment.exe info
```

Вход и выход: PGM P5, восемь бит, maxval=255. Выход — байты 0/255. Стороны положительны. Ошибки ввода сообщаются в stderr с ненулевым кодом возврата. Файл назначения записывается после успешного расчёта. Однотонный вход: T=его яркость, маска нулевая. При равных максимумах критерия сохраняется меньший порог. Внутри используется `long double`; математически почти равные критерии на иных входах могут различаться из-за округления. Во всех 210 независимых проверках получено точное совпадение с рациональным эталоном.

## Повторить исследование

```powershell
./build.ps1 -Benchmark
./build.ps1 -Report
```

Исследование выполняется сборкой **-O0**, без отладочной информации; 100 повторений на конфигурацию, один прогрев, циклическое чередование порядка конфигураций. Таймер QueryPerformanceCounter измеряет реальное время, включая создание и завершение потоков, выделение служебной памяти и синхронизацию. Генерация, файловый ввод-вывод, выделение входа/выхода, проверка маски и запись CSV исключены. Потоки заново создаются для каждого измерения. Сохранение новой серии заменяет CSV и графики; текст выводов отчёта следует сверить с новыми числами.

На исследованной машине: Intel Core i3-1115G4, 2 физических / 4 логических ядра, q=1,2,4,8,16,32; размеры 256²–4096², всего 3500 измерений. Для 4096²: последовательная версия 132,034 мс, параллельная q=1 — 173,095 мс; минимальное среднее при q=8 — 73,955 мс, ускорение 1,79. Разброс достаточно велик, чтобы не считать близкие конфигурации q=8/16/32 устойчиво различимыми. Условия обычной настольной системы, фоновые приложения и динамическая частота не изолированы.

## Состав

- `src/segmentation.c`, `.h` — вычисления и синхронизация, код в отчёте подключён напрямую.
- `src/main.c` — командный интерфейс и серия замеров; `src/image.c` — генератор, PGM, таймер.
- `tests/test_api.c` — ошибки API, работа в одном буфере, остаток деления, q>N.
- `tests/test_launch_failure.c` — четыре искусственных отказа создания потока с проверкой завершения созданных рабочих и сохранности выхода.
- `tests/verify.py` — независимый эталон с `Fraction`, 30 изображений × 7 режимов, PGM/CLI.
- `results/tests.txt`, `raw.csv`, `summary.csv`, `environment.json` — фактические протоколы, статистика и хеши измеренной версии.
- `scripts/analyze.py` — сводные таблицы и графики; `scripts/environment.py` — сведения о Windows и машине.
- `scripts/check_artifacts.py` — проверка хешей измеренной версии, полноты CSV и повторного расчёта средних.
- `scripts/make_example.py` — повторное получение фантома, сравнение двух масок и создание иллюстрации отчёта.
- `figures/*.tex` — редактируемые векторные схемы потоков; PDF/PNG — графики и пример.
- `docs/phantom.pgm`, `docs/mask.pgm` — пример входа и выхода; это синтетический фантом, не снимок пациента.
- `docs/TASK.md` — задание, разбор шести фото и решения по неоднозначностям; `docs/otsu1979.pdf` — исходная статья.
- `Makefile` — альтернативные цели all/test/benchmark/report. Вычислительный C-код также поддерживает POSIX-системы; скрипт сведений о среде рассчитан на Windows.

После сборки отчёт проверен по извлечённому тексту и отрисованным страницам; результат проверки — `results/pdf-verification.txt`.

Титульные реквизиты подтверждены пользователем по примерам ЛР1–3: Понарин А. А., ИУ7-55Б, Волкова Л. Л., Строганов Д. В. При необходимости измените `report.tex` и пересоберите отчёт.
