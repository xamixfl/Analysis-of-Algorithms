# Лабораторная работа № 3. Рекурсивные и нерекурсивные алгоритмы

Вариант U — разворот числа без нулевых цифр. Работа целиком находится в этой папке.

- `report.pdf` — готовый отчёт.
- `report.tex` — исходник отчёта, оформление перенесено из `../lab1/report.tex`.
- `algorithms.cpp`, `algorithms.hpp`, `main.cpp` — программа на C++17.
- `figures/*.tex` — две блок-схемы и восемь графовых моделей, векторные рисунки TikZ.
- `generate_figures.py` — воспроизводит рисунки и машинное описание дуг.
- `results/test_results.txt` — фактические результаты проверок.
- `results/graph_models.json` — обозначения вершин и множества дуг.

## Сборка и запуск (Windows, PowerShell)

Нужен компилятор C++17, например GCC. Сборка и автоматические проверки:

```powershell
powershell -ExecutionPolicy Bypass -File .\build.ps1
```

Или сборка программы отдельно:

```powershell
g++ -std=c++17 -O2 -Wall -Wextra -Wpedantic main.cpp algorithms.cpp -o reverse_number.exe
"179" | .\reverse_number.exe recursive
"179" | .\reverse_number.exe iterative
"179" | .\reverse_number.exe both
```

Первые два режима выводят `971`. Режим `both` проверяет совпадение и выводит:

```text
iterative: 971
recursive: 971
```

Можно запустить `./reverse_number.exe recursive`, ввести число и нажать Enter.
Допускается одно натуральное число в одной строке, без знака и нулевых цифр,
от 1 до 9999999999999999999 (до 19 цифр). Пробелы по краям разрешены.
Ноль, отрицательные числа, знак `+`, ведущие нули, несколько чисел и превышение
диапазона отклоняются. Код завершения: 0 — успех, 1 — ошибка данных,
2 — неверный режим, 3 — несовпадение результатов в режиме сравнения.

Диапазон выбран так, чтобы число и разворот всегда помещались в `std::uint64_t`.
Числа из 20 цифр отклоняются, даже если некоторые из них представимы этим типом.
Рекурсивное ядро и проверка его аргумента не используют циклы, строки, массивы
или списки. Для требуемого общим заданием сравнения добавлено нерекурсивное
решение с циклом. Обе функции возвращают целое число.

Альтернативная сборка через CMake:

```powershell
cmake -S . -B build
cmake --build build
ctest --test-dir build --output-on-failure
```

Для многоконфигурационного генератора добавьте `--config Release` к сборке
и `-C Release` к `ctest`. Проверки CLI в этой конфигурации запускайте отдельно,
либо используйте `build.ps1`, размещающий основной exe в корне лабораторной.

## Проверки

`tests/test_algorithms.cpp` проверяет 10 фиксированных, 19000 генерируемых
допустимых и 7 недопустимых наборов. В каждом проверяются обе реализации;
для допустимых также проверяется двойной разворот. Числовой эталон строится
одновременно с исходным числом, без вызова проверяемых функций.
`tests/verify_cli.py` проверяет ещё 40 случаев консольного интерфейса.
`tests/verify_models.py` независимо прослеживает происхождение данных при
`n=179`, сравнивает дуги информационных историй, проверяет ацикличность
и совпадение проекции историй с компактными информационными графами.

## Сборка отчёта

Нужны XeLaTeX (MiKTeX или TeX Live), TikZ, polyglossia, fontspec и стандартные
пакеты из преамбулы. В Windows используются системные Times New Roman,
Consolas и Courier New. Для другой ОС замените три настройки шрифтов
в начале `report.tex` на доступные шрифты.

```powershell
python generate_figures.py
python tests/verify_models.py
xelatex -interaction=nonstopmode -halt-on-error report.tex
xelatex -interaction=nonstopmode -halt-on-error report.tex
```

Или `powershell -ExecutionPolicy Bypass -File .\build.ps1 -Report`.
Все схемы включаются через `\input` как векторные объекты. Единственная
растровая иллюстрация — герб на титульном листе, скопированный из образца.
Формат A4, Times New Roman 14 пт, интервал 1,5, поля 30/15/20/20 мм и отступ
1,25 см сохранены из образца. Титульные данные также сохранены из образца.

Третий раздел содержит реализацию и тестирование, четвёртый — все четыре
модели для каждого алгоритма и анализ параллелизма исходного кода.
Истории показывают полное выполнение при `n=179`. В рекурсивных моделях
передача аргументов (`R6a`) отделена от получения результата (`R6b`);
источник ответа — возврат из соответствующего потомка.

Замеры времени не проводились: по заданию сравнение основано на графовых
моделях. Программа последовательная; параллельное выполнение обосновано
в отчёте, без запуска многопоточной версии.
