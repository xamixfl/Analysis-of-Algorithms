     Полутоновое изображение представляет собой прямоугольную
матрицу яркостей без цветовых каналов. Сегментацией называется
разбиение его пикселей на классы. При пороговой сегментации классы
определяются сравнением яркости с порогом. Такой способ применим к
изображениям, для которых достаточно выделить две группы яркостей.
     Цель работы — разработать последовательный и параллельный
алгоритмы сегментации полутоновых изображений, реализовать их и
исследовать зависимость реального времени расчёта от числа рабочих
потоков.
     Для достижения цели необходимо:
     — выбрать метод сегментации и определить входные и выходные
         данные;
     — разработать алгоритмы и схемы последовательного потока,
         диспетчера и рабочего потока;
     — реализовать алгоритмы на языке Си и выполнить функциональное
         тестирование;
     — измерить реальное время последовательной и параллельной
         реализаций при числе рабочих потоков от одного до
         восьмикратного числа логических ядер;
     — сравнить результаты и определить влияние размера изображения и
         числа рабочих потоков.

     1.3 Возможности распараллеливания
     Построение гистограммы и применение готового порога требуют
обхода всех пикселей. При непосредственном изменении общей
гистограммы потребовалась бы синхронизация каждого приращения.
Вместо этого каждый рабочий поток формирует собственные 256 счётчиков;
после завершения этой фазы диспетчер суммирует их.
     Порог зависит от всех локальных гистограмм. Поэтому бинаризацию
нельзя начинать до окончания их объединения и поиска порога. После
публикации порога каждый рабочий поток обрабатывает назначенный ему
диапазон пикселей. Диапазоны разных потоков не перекрываются, поэтому
два потока не записывают результат в один и тот же пиксель маски.
Используется параллелизм по данным со статическим распределением
пикселей.
     Метод Оцу требует только гистограмму и не нуждается в заданном
вручную пороге. Однако при неоднородном освещении и перекрывающихся
распределениях яркости одной границы может быть недостаточно. В работе
сравниваются реализации выбранной бинарной сегментации; точность
выделения органов по клинической разметке не оценивается.

     2.2 Распределение работы
      Число рабочих потоков обозначается q. Диспетчер не входит в это
число и не обрабатывает собственный участок изображения. Рабочему j,
0 ≤ j < q, назначается полуинтервал [bj , ej ):
                        d = ⌊N /q⌋, r = N mod q,
                      bj = j · d + min(j, r),                      (5)
                      ej = bj + d + [j < r].
Размеры участков различаются не более чем на один пиксель. Первый
участок начинается с нуля, последний заканчивается на N , а конец
каждого участка совпадает с началом следующего. Поэтому каждый пиксель
обрабатывается ровно одним рабочим. При q > N часть участков пуста, но
фактически создаются все заданные q потоков.
     Для связи потоков используются мьютекс, то есть средство
взаимоисключающего доступа к состоянию синхронизации, и две условные
переменные для ожидания изменений этого состояния. Счётчик c хранит
число построенных гистограмм, флаг p разрешает бинаризацию, флаг
a обозначает отмену запуска. Начальные значения равны нулю. Все
обращения к этим переменным и публикация общего порога защищены
одним мьютексом.


     2.3 Алгоритм потока-диспетчера
     После выделения памяти под локальные гистограммы и описатели
создаются рабочие потоки. Диспетчер ожидает готовности всех
гистограмм, объединяет их и вычисляет порог. Затем устанавливается
флаг разрешения второй фазы, пробуждаются все ожидающие рабочие и
освобождается мьютекс. Завершение каждого созданного потока ожидается
до освобождения его данных. При неудачном запуске очередного рабочего
устанавливается флаг отмены; уже созданные рабочие пробуждаются и
завершаются без бинаризации.

     Ожидание условной переменной временно освобождает мьютекс;
после пробуждения он вновь захватывается [2]. Предикат ожидания

преждевременную бинаризацию. После копирования порога мьютекс
освобождается.
     Локальные гистограммы принадлежат разным рабочим, поэтому при
подсчёте частот конфликтов записи нет. Для каждого уровня яркости
сумма локальных счётчиков совпадает со счётчиком последовательной
версии. Суммирование целочисленное, порядок объединения результата не
изменяет. В обеих версиях применяется одна процедура определения порога,
включая правило выбора при равенстве критерия.

последовательным результатом.


     2.6 Оценка затрат ресурсов
     Пусть L = 256 — число уровней яркости. Последовательная
трудоёмкость составляет O(N + L), дополнительная память без учёта входа
и маски — O(L). Суммарная работа параллельной версии равна O(N + q · L),
дополнительная память — O(q · L + q). Для маски в обеих версиях требуется
ещё N байт.
     При одновременном исполнении всех рабочих и равномерной загрузке
оценка вычислительной части критического пути равна
                           (                 )
                         O ⌈N /q⌉ + q · L + L .                       (6)
К реальному времени добавляются расходы на выделение памяти, запуск,
синхронизацию и завершение потоков. При q больше числа доступных
логических ядер все рабочие одновременно не исполняются, поэтому
член N /q не описывает фактическое сокращение времени. Объединение
гистограмм и поиск порога остаются последовательными этапами.


     2.7 Требования к программе и тестирование
     Программа читает и записывает двоичные полутоновые изображения
PGM с сигнатурой P5 и максимальным значением 255. Нулевые
размеры, переполнение размера, усечённый растр, лишние байты и
неподдерживаемый формат отклоняются. Число рабочих потоков задаётся
явно в диапазоне от 1 до 4096. В библиотечных функциях допускается
использование одного буфера для входа и результата; частичное перекрытие
буферов не допускается.
     Для проверки выбраны изображения с заранее определяемыми
порогом и маской: однотонные, бинарные, с двумя различными яркостями и

     3 Технологическая часть

     3.1 Средства реализации
      Реализации написаны на языке Си (C), стандарт 2011 года (C11). Для
потоков, мьютекса и условных переменных применяется интерфейс
потоков POSIX в реализации winpthreads, поставляемой с MSYS2.
Использован компилятор GCC 14.2.0, среда UCRT64. Измерительная
сборка выполняется с параметрами -std=c11 -O0 -Wall -Wextra -Wpedantic
-pthread, без отладочной информации и без оптимизации.
      Счётчики гистограммы имеют тип беззнакового 64-разрядного целого
числа. Размер изображения ограничен условием N ≤ ⌊(264 − 1)/255⌋
и доступной памятью. Это исключает переполнение суммы яркостей.
Критерий Оцу вычисляется с использованием вещественного типа
расширенной точности long double; поэтому для практически равных
максимумов на иных больших входах округление может влиять на
выбранный порог. В функциональных проверках совпадение с точным
эталоном подтверждено. Между последовательной и параллельной версиями
порядок вычисления критерия одинаков.
      Исходные тексты разделены на модули сегментации, обработки
изображений и командного интерфейса. Основные функции подключены
непосредственно из исходных файлов в приложении А. Один локальный
массив гистограммы занимает 2048 байт, q таких массивов — 2048 · q байт.
Дополнительно выделяются описатели потоков и структуры синхронизации;
память стеков управляется библиотекой потоков и операционной системой.

 7 unsigned otsu_threshold(const uint64_t h[LEVELS], size_t n)
 8{
 9 uint64_t total = 0, left_sum = 0, left_count = 0;
10 unsigned best = 0, only = 0;
11 long double maximum = −1.0L;
12 for (unsigned v = 0; v < LEVELS; ++v) {
13       total += (uint64_t)v * h[v];
14       if (h[v]) only = v;
15 }
16 for (unsigned t = 0; t < LEVELS − 1; ++t) {
17       left_count += h[t];
18       left_sum += (uint64_t)t * h[t];
19       if (left_count == 0 || left_count == n) continue;
20       long double delta = (long double)n * left_sum
21                    − (long double)left_count * total;
22       long double score = delta * delta /
23          ((long double)left_count * (n − left_count));
24       if (score > maximum) { maximum = score; best = t; }
25 }
26 /* Empty class at every threshold: choose the only occupied level. */
27 return maximum < 0.0L ? only : best;
28 }
